# Integrated Writers Editor (IWE)

English version → [README.md](README.md)

長編小説（数話〜約500話規模）のためのAI執筆支援アプリです。キャラクター・世界観・プロット・伏線・年表という構造化されたストーリーデータをAIが本文生成前に必ず参照する仕組みにより、長期にわたる作品でも設定の一貫性を保ちます。すべて自分のPC・サーバー上で動作し、ローカルの[Ollama](https://ollama.com)を使用します。外部クラウドAI APIへは接続しません。

## クイックスタート

```bash
cp .env.example .env   # ADMIN_PASSWORD（必須）とOllamaのURLを必要に応じて編集
docker compose up --build
```

Webアプリは `http://localhost:3000`（ユーザー名`admin`と設定した`ADMIN_PASSWORD`でログイン）、APIのインタラクティブドキュメントは `http://localhost:8000/docs` で開けます。Dockerを使わない構築方法も含めた詳細は[インストールマニュアル](docs/installation.ja.md)を参照してください。

ターミナル操作をしたくない場合は、[Releasesページ](https://github.com/itanaka66/integrated_writers_editor/releases)から**Windows（`.exe`）**または**macOS（`.pkg`）**のデスクトップインストーラをどうぞ。Docker Desktopは別途必要ですが、それ以外はインストーラが行い、「起動」「停止」ショートカットが作成されます。詳しくは[installer/](installer/)とインストールマニュアルのデスクトップインストーラの項目を参照してください。

ローカルOllamaのモデル取得：
```bash
ollama pull qwen3:8b        # 手動AI支援（執筆画面・チャット）
ollama pull qwen3.8:27b     # 自動執筆のWriter（既定値）
ollama pull qwen3:14b       # 自動執筆のController（既定値）
ollama pull nomic-embed-text  # RAG用埋め込みモデル
```

## 機能概要

- **構造化されたストーリーデータ**：キャラクター、世界観、プロット、伏線、年表。それぞれ作成・編集・削除に対応し、用語集ビュー（`glossary`タグ付きの世界観データ）も利用できます。これらすべてが、本文生成時・連続性チェック時にAIのコンテキストとして使われます。
- **AI執筆アシスタント**：現在のエピソードの続き執筆／要約／校正、時系列・人物状態・世界観・伏線・プロット・文章品質をチェックする6つのクイックプロンプト、履歴が保存される作品ごとの自由対話AIチャット。いずれも同じContext Builderを基盤としています。
- **エディタ**：軽量なMarkdownツールバー（太字/斜体/見出し/引用）とプレビュー表示、変更履歴（1エピソードあたり直近20件・復元可能）、リアルタイム文字数表示。
- **連続性監査**：時系列・人物状態・世界観・伏線をまたいだ矛盾をAIが検出し、深刻度と修正案を提示します。あくまで一次チェックであり正解ではないため、結果は必ず人間が確認してください。
- **キャラクター状態の追跡**：エピソード保存後、AIが本文から状態変化（状態・場所・感情・健康・目標・知識）を抽出し、キャラクターの基本プロフィールとは別に履歴として記録します。
- **Story Digital Twin**（`GET /api/v1/projects/{id}/story-twin`）：作品の健全性スコア、本文カバレッジ、関係グラフ（人物／世界観／時系列）、直近のキャラクター状態履歴、未解決の連続性課題を1つにまとめたビュー。アプリ内では「分析」画面として表示されます。
- **セマンティック検索（RAG）**：Qdrantによる本文検索。Qdrantに接続できない場合はPostgreSQLの部分一致検索へ自動フォールバックし、検索画面にはどちらが実際に使われたかが表示されます。現在の作品だけでなく、全作品を横断して検索することもできます。
- **テキストファイルからのインポート**：「なろう」形式のエクスポートファイルから既存の小説を取り込めます。メタ情報付きの本編ファイル（タイトル・あらすじ・ジャンルから新規作品を作成し全エピソードを登録）と、メタ情報のない下書きエピソードファイル（既存作品にエピソードを追加・更新）の両方に対応。取り込んだ話ごとに再索引付けと通常保存時と同じキャラクター状態抽出を行い、最後に1回の連続性監査を実行するため、進捗確認可能なバックグラウンドジョブとして実行されます。
- **プレーンテキスト検索・全置換**：作品内の全エピソードを対象に文字列を検索し、一括置換できます。置換前にエピソードごとのプレビュー・選択ができ、置換前の内容は自動的に改訂履歴に保存されるため、いつでも元に戻せます。
- **ローカルディスクへのミラー＋GitHub自動保存**：エピソード保存のたびにMarkdownのコピーをディスクにも書き出し、gitリモートを設定していればバックグラウンドでタイマーごとに自動コミット・プッシュします。データベースとは別に、エピソード本文をファイルとしてバックアップできます。
- **バックグラウンドジョブの完了通知**：自動執筆やファイルインポートのジョブを開始するとブラウザの通知許可を求め、終了時（完了／停止／エラー）にデスクトップ通知が届きます。タブを開いたままにしておけば、進捗バーを見続ける必要がありません。
- **自動バックアップのスケジュール実行**：PostgreSQLのダンプとQdrantのスナップショットをタイマーで自動取得するバックグラウンドジョブ（既定オフ、オプトイン）。自動保持件数管理付き。設定画面から「今すぐバックアップ」ボタンでの即時実行と履歴確認もできます。詳しくは[設定＞バックアップとリストア](docs/user-guide.ja.md#バックアップとリストア)を参照してください。
- **接続設定のライブ変更**：QdrantとOllamaの両エンドポイント（Writer／Controller）を設定＞接続設定画面から変更でき、再起動なしで即座に反映されます。各項目（読み取り専用のデータベース欄も含む）に「接続テスト」ボタンがあり、保存前に今入力中の値をその場でテストできます。
- **エクスポート**：作品のエピソードをテキスト・Markdown・簡易EPUB3のいずれかでダウンロードできます。
- **自動執筆**：Series（1〜500話全体）→ Arc（100話単位×5）→ Mini Arc（10話単位×各アーク内10個）→ 話ごとの執筆計画という4階層の計画を、独立した「Controller」Ollamaモデルが管理し、本文自体は「Writer」Ollamaモデルが生成します。Controllerは執筆前後の品質チェック（時系列／人物／世界観／プロットのみ。文章の巧拙は判定しません）も行い、必要なら再執筆を強制します。既存エピソードは既定でスキップ（上書きは任意）。5話ごとに連続性の全体監査も自動実行されます。進捗（パーセンテージ、フェーズ、各階層の計画策定数）はAPIで取得でき、「自動執筆」画面に表示されます。詳しい仕組みは[操作マニュアルの自動執筆の項目](docs/user-guide.ja.md#自動執筆)を参照してください。
- **決定論的なPlanner構造検証**：AIが生成した計画の「内容」とは別に、`apps/api/app/planner/structure_validator.py`がSeries→Arc→Mini Arc→Episode階層の「構造」——ちょうど5アーク×各100話、各アーク内ちょうど10ミニアーク×各10話、欠番・重複・範囲の重なりがなく1〜500話を完全にカバーしていること——を、LLMの生成結果に関わらず検証します。

## アーキテクチャ

| | |
|---|---|
| バックエンド | FastAPI + SQLAlchemy 2.0、Python 3.13、Alembicマイグレーション |
| フロントエンド | Next.js 16（App Router）+ React 19、TypeScript |
| データベース | PostgreSQL（ストーリーデータ） |
| ベクトルストア | Qdrant（セマンティック検索の索引） |
| LLM実行環境 | Ollama（ローカル実行）。Writer / Controllerの2つのモデルロールを設定可能 |
| 認証 | 共有のHTTP Basic認証アカウント1つのみ（`ADMIN_USERNAME`/`ADMIN_PASSWORD`）。個人ごとのアカウントやOAuthはなし |
| CI | GitHub Actions：ruff＋pytest＋Alembicマイグレーションの往復確認（バックエンド）、eslint＋Vitest＋`next build`（フロントエンド） |

Ollama呼び出し（`generate`/`embed`）は、一時的なネットワーク障害に対して最大3回までバックオフ付きでリトライします。セルフホスト環境向けに、PostgreSQL＋Qdrantのバックアップ/リストアを行う`scripts/backup.sh`/`scripts/restore.sh`も用意しています（[操作マニュアルのバックアップとリストアの項目](docs/user-guide.ja.md#バックアップとリストア)参照）。

## 既知の制限

- 共有パスワード1つのみで、個人ごとのアカウントや権限管理はありません（[操作マニュアル→ログイン](docs/user-guide.ja.md#ログイン)参照）。
- 「AI設定」画面は、そのブラウザでの自動執筆フォームの初期値となるモデル名を設定するだけです。バックエンドが実際に接続するOllamaサーバー（サーバー側の`OLLAMA_URL`/`CONTROLLER_OLLAMA_URL`）は変更されません。
- エディタのMarkdownツールバー/プレビューはリッチテキストエディタではありません。保存される内容は常にプレーンなMarkdownテキストです。
- 利用状況・トークン使用量を記録するダッシュボードはまだありません。
